Finds the interceptor. Never reads the traffic.

This sensor finds an attacker between a client and a website. It reads only the TLS handshake and does not decrypt the traffic.

How it works.

The sensor uses the Threshold Random Walk method (Jung and others, 2004). It adds small signs from many sites until it can make a decision.

  1. The interceptor does not have the private key of each real server. Thus the handshake of each site changes a little.
  2. One change is weak evidence, because real sites also change. Many changes on many sites for one client are strong evidence.
  3. Each client has a score that starts at 0. A mismatch adds +2.08 and a match adds −1.50.
  4. At +4.60 the sensor sends an alert. At −4.60 it clears the client. After each decision, a new test starts at 0.

Architecture.

Packets go in, and one score for each client comes out. The sensor reads only the handshake and does not decrypt the traffic.

Capture

libpcap

The sensor reads packets from a mirror port or a PCAP file. It keeps only the TCP packets.

TCP reassembly

src/sensor.cpp

The sensor puts the TCP pieces in the correct sequence. It keeps only the first bytes, because the handshake is there.

3

TLS parser

src/tls.cpp

The parser reads the ClientHello, the ServerHello and the certificate. It does not decrypt the traffic.

4

Fingerprints

OpenSSL · SHA-256

The sensor makes the JA4 and JA4S fingerprints and a hash of the server key. These values identify the TLS software and the server.

Checks A, B, D

TRW score

src/trw.cpp

The sensor adds +2.08 for a mismatch and −1.50 for a match. At +4.60 it sends an alert, and at −4.60 it clears the client.
