Data path

The live page does not use simulated data. A Linux VM on Vercel connects to real sites. tcpdump records the packets. The C++ sensor reads the packets and the engine decides.

Your browser

Live page

You type 3 to 8 sites and push Learn or Run test. The page shows each handshake when it arrives.

Internet

Real sites

Each site keeps one IPv4 address for the session, so the two visits go to the same server.

Step 1. Learn

One time for each VM.

  1. The function starts a new VM from a snapshot. This takes 1 to 3 seconds.
  2. The VM makes the client network and finds one IPv4 address for each site.
  3. tcpdump starts. It is a program that records network packets and saves them in a file (a PCAP). Then the client visits each site one time.
  4. After each visit, zerohour show reads the PCAP and gives JA4S, certificate key and TTL.
  5. These handshakes are the baseline. You can download learn.pcap.

Step 2. Test

One test for each VM. Then the VM stops.

  1. The scenario sets the change for each site: none, new route, new TLS settings, or mitmproxy.
  2. The client visits each site again. tcpdump records test-N.pcap.
  3. The engine compares each handshake with the baseline: checks A (JA4S), B (key), D (TTL).
  4. The tuned TRW adds one step for each site. At +4.60 it alerts.
  5. Each notice and verdict goes into the BLAKE2b-256 hash chain in the VM.
